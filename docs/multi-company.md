# หลายบริษัท (แบบ FA) — บันทึกออกแบบ ยังไม่ทำ (เจ้าของระบบ 17-11-2026: "ยังไม่ต้องทำตอนนี้")

## ที่ตรวจใน FA จริง (17-11-2026)
- ผู้ใช้ 1 บัญชีล็อกอินครั้งเดียว ใช้ได้หลายบริษัท · หน้า "เลือกธุรกิจที่คุณต้องการใช้งาน" (ค้นหาชื่อบริษัท/สาขา · การ์ดแสดงชื่อ รหัสบริษัท เช่น N5670322 และสาขา · ปุ่ม "สร้างธุรกิจใหม่")
- สลับระหว่างใช้งาน: dropdown ชื่อบริษัทมุมขวาบน หรือ เมนูโปรไฟล์ซ้ายล่าง › เลือกธุรกิจ (มี "แสดงทั้งหมด" ไปหน้าเลือกบริษัท · จุดเขียว = บริษัทที่ใช้อยู่)
- รหัสบริษัทอยู่ใน URL ทุกหน้า (/N5670322/...) → เปิดหลายบริษัทคนละแท็บได้
- ข้อมูลแยกกันทั้งหมด: ผังบัญชี เอกสาร ตั้งค่า ผู้ใช้/สิทธิ์ต่อบริษัท

## ข้อกำหนดเพิ่มจากเจ้าของระบบ
- ต้องมีรายงานรวมข้ามบริษัท (เช่น งบรวม ยอดขายรวม) — FA ไม่มี

## แนวทางที่เสนอ (รอเริ่มงาน)
- แยก schema ต่อบริษัทในฐานเดียว (`co_<รหัส>`) · ฟังก์ชันลงบัญชีเดิมใช้ต่อได้ผ่าน `search_path` ต่อ request (ต้อง `set local` ในทรานแซกชัน เพราะ Supabase pooler แบบ transaction)
- schema กลาง: บริษัท ผู้ใช้ สิทธิ์ต่อบริษัท · migration รันวนทุก schema
- รายงานรวม: ฟังก์ชันใน schema กลาง union ข้อมูลจากทุก schema ที่ผู้ใช้มีสิทธิ์ · ผังบัญชีต้องเทียบรหัสกันได้ (ใช้ผังเดียวกันเป็นค่าเริ่มต้น) · ต้องตัดรายการระหว่างกัน (intercompany) สำหรับงบรวม → ต้องกำหนดรายชื่อคู่ค้าที่เป็นบริษัทในเครือ
- ทางเลือกที่ไม่แนะนำ: เพิ่ม company_id ทุกตาราง (ต้องแก้ทุกฟังก์ชัน เสี่ยงข้อมูลข้ามบริษัท)
